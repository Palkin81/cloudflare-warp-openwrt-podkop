# Сборка для OpenWrt 25.12 x86_64 (форк)

Этот форк собирает APK-пакеты `warp-awg`, `warp-warpscout` и `luci-app-warp`
для **OpenWrt 25.12.x, x86_64** (виртуальные машины, мини-ПК, x86-роутеры).
Исходный проект ориентирован на `aarch64_cortex-a53`; код пакетов здесь не
меняется, добавлены только сборка на GitHub Actions и проверки результата.

Один и тот же комплект APK подходит для всех релизов 25.12.x: внутри Go-бинарники
и скрипты, привязки к конкретной версии ядра или musl нет (проверено установкой
на 25.12.3 и 25.12.6). Собирается он на самом свежем SDK из закреплённых.

## Установка на роутер

Скрипт установки из основного README рассчитан на `aarch64` и для x86_64 не
подходит. Берите APK из последнего релиза форка (раздел Releases) и ставьте вручную.

Подписанные пакеты (после первой настройки ключа, см. ниже):

```sh
apk add ./warp-awg-*.apk ./warp-warpscout-*.apk ./luci-app-warp-*.apk
```

Пока ключ не настроен, пакеты не подписаны постоянным ключом:

```sh
apk add --allow-untrusted ./warp-awg-*.apk ./warp-warpscout-*.apk ./luci-app-warp-*.apk
```

Зависимость `kmod-tun` подтянется из репозиториев OpenWrt. Дальше настройка
через LuCI: **Службы → Cloudflare WARP**.

Если вы меняли `/etc/config/warp`, при обновлении `apk` оставит ваш файл, а
новый сохранит как `/etc/config/warp.apk-new`.

## Подпись пакетов

SDK подписывает только индекс репозитория, поэтому отдельные APK подписывает
workflow (`apk adbsign`) вашим постоянным ключом и тут же проверяет подпись.

Один раз на своём компьютере:

```sh
openssl ecparam -genkey -name prime256v1 -noout -out private-key.pem
openssl ec -in private-key.pem -pubout -out public-key.pem
```

1. Приватный ключ целиком (с строками `BEGIN`/`END`) добавьте в секреты форка:
   Settings → Secrets and variables → Actions → секрет `APK_SIGN_KEY`.
   Сохраните его копию у себя: GitHub обратно секрет не показывает. Потеряете —
   придётся создать новый ключ и заново раздать публичный. В репозиторий ключ
   не коммитьте.
2. Публичный ключ положите на роутер под уникальным именем (у OpenWrt нет
   `sftp-server`, поэтому для `scp` нужен флаг `-O`):

   ```sh
   scp -O public-key.pem root@192.168.1.1:/etc/apk/keys/warp-fork.pem
   echo /etc/apk/keys/warp-fork.pem >> /etc/sysupgrade.conf
   ```

   Публичный ключ также лежит в каждом релизе рядом с APK. Строка в
   `/etc/sysupgrade.conf` нужна, чтобы ключ пережил обновление прошивки.

Без секрета `APK_SIGN_KEY` сборка проходит, но пакеты остаются неподписанными;
workflow при этом проверяет схему подписи на одноразовом ключе.

## Как работает сборка

Файл: `.github/workflows/build-x86_64.yml`.

- **Запуск.** Ежедневно по расписанию (на `main`), вручную (Actions → Build APK →
  Run workflow) и при пуше в ветки `ci/**`. По расписанию сначала подтягиваются
  изменения основного репозитория; если новых коммитов нет, сборка пропускается.
- **SDK.** OpenWrt SDK 25.12.6 x86/64. Контрольная сумма закреплена в workflow и
  на каждом запуске сверяется с официальными `sha256sums`. Feeds берутся из
  самого SDK, то есть закреплены на коммиты этого релиза.
- **Go.** `warp-awg` требует Go 1.26.3 или новее. Если в feeds версия старше,
  применяется `ci/golang-changes.patch`; в 25.12.6 Go уже 1.26.9, патч не нужен.
- **Зависимость `kmod-tun`.** В сборочных зависимостях она заставляет SDK
  собирать ядро и скачивать `linux-firmware` (сотни мегабайт). Поэтому в SDK-копии
  `warp-awg/Makefile` она переносится в `EXTRA_DEPENDS` и остаётся только
  зависимостью установки. Файл в репозитории остаётся как в основном проекте.
- **Минимальный конфиг.** Отключены `CONFIG_ALL` и `CONFIG_ALL_KMODS`, собираются
  только три нужных пакета.
- **Режимы файлов.** В git скрипты в `root/usr/libexec` и `root/etc/init.d` записаны
  как 0644, а LuCI запускает их напрямую. Перед сборкой выставляется 0755.
- **Проверки** (`ci/check-packages.sh`): по одному APK на пакет, обязательные
  файлы, режимы 755, ELF именно x86-64, архитектура в метаданных, зависимость
  `kmod-tun` в `warp-awg`. Затем подпись и контрольные суммы `SHA256SUMS`.
- **Результат.** Артефакт `warp-apk-x86_64` (30 дней) и релиз `build-<коммит>`
  при запуске на `main`.

## Обслуживание

- **Новая версия OpenWrt.** В `build-x86_64.yml` замените пять значений
  `SDK_VERSION`, `SDK_SHA256`, `SDK_BASE`, `SDK_ARCHIVE`, `SDK_DIR`. Сумму берите
  из `https://downloads.openwrt.org/releases/<версия>/targets/x86/64/sha256sums`.
- **Если сборка упала на feeds или Go.** Сообщение в логе укажет, чего не хватает
  (например, пропала ветка `golang1.26`); тогда патч Go нужно обновить.
- **Конфликт слияния с основным репозиторием.** Если upstream изменит
  `.github/workflows/`, автоматическое слияние `GITHUB_TOKEN` не сможет запушить.
  Слейте изменения вручную.

## Что не проверено

Установка на роутер подтверждена на 25.12.3 и 25.12.6. Работа с подписью
постоянным ключом на реальном роутере и отдельные версии 25.12.0–25.12.2 не
проверялись.
